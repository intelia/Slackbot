## 2. Create and configure the Slack app

The bot uses **Socket Mode**, which means it connects outward to Slack over a WebSocket — no public URL or ngrok needed.

### 2.1 Create the app

1. Go to [api.slack.com/apps](https://api.slack.com/apps) and click **Create New App**.
2. Choose **From scratch**.
3. Name it `Zupa Order Parser` (or any name), select your workspace, click **Create App**.

### 2.2 Enable Socket Mode

1. In the left sidebar, go to **Socket Mode**.
2. Toggle **Enable Socket Mode** to ON.
3. You will be prompted to create an **App-Level Token**. Name it `zupa-socket`, select the `connections:write` scope, and click **Generate**.
4. Copy the token — it starts with `xapp-`. This is your `SLACK_APP_TOKEN`.

### 2.3 Add OAuth scopes (Bot Token)

1. In the sidebar, go to **OAuth & Permissions**.
2. Under **Bot Token Scopes**, click **Add an OAuth Scope** and add all of the following:

   | Scope | Why |
   |---|---|
   | `chat:write` | Post and update review messages |
   | `chat:write.public` | Post to channels the bot hasn't joined |
   | `commands` | Register the `/parse-order` slash command |
   | `users:read` | Resolve `confirmed_by` user ID to a display name (optional) |

3. Scroll up and click **Install to Workspace**. Approve the permissions.
4. Copy the **Bot User OAuth Token** — it starts with `xoxb-`. This is your `SLACK_BOT_TOKEN`.

### 2.4 Copy the Signing Secret

1. In the sidebar, go to **Basic Information**.
2. Under **App Credentials**, copy the **Signing Secret**. This is your `SLACK_SIGNING_SECRET`.

### 2.5 Register the slash command

1. In the sidebar, go to **Slash Commands** → **Create New Command**.
2. Fill in:
   - **Command:** `/parse-order`
   - **Short description:** `Parse a WhatsApp/IG DM order`
   - **Usage hint:** `(paste raw order text in the modal)`
   - Request URL: leave as-is (Socket Mode ignores this field)
3. Click **Save**.

### 2.6 Enable Interactivity

1. In the sidebar, go to **Interactivity & Shortcuts**.
2. Toggle **Interactivity** to ON.
3. Request URL: enter any placeholder URL (e.g. `https://example.com/slack/events`) — Socket Mode doesn't use it, but the field is required.
4. Click **Save Changes**.

### 2.7 Subscribe to events (optional — needed for DM intake in Phase 2)

For Phase 1 staff use the slash command, so no event subscriptions are required. Skip this for now.

## 5. Run Phase 0 — data cleaning

This step cleans the raw data files and produces the lookup indexes the parser uses. Run it once before starting the bot, and again any time `products.json` or `cities.json` are updated from Zupa.

```bash
npm run clean-data
```

Expected output:

```
Products: 211 raw → 208 clean, 18 null sizes stripped
Cities: 261 raw → 220 named zones, 36 ride-hail tiers, 5 pickup rows
✓ Wrote src/data/products.clean.json
✓ Wrote src/data/cities.clean.json
✓ Wrote src/data/alias-map.json (seed)
```

What the script does:

- **Products:** strips `null` size entries (18 found), removes trailing whitespace from names, deduplicates entries with the same name (keeps the one with more complete size data).
- **Cities:** trims whitespace, classifies every zone as `named_zone` / `ride_hail_tier` / `pickup`, extracts branch routing hints (`Mainland Store`, `Opebi Store`, or defaults to `Lekki`), and pairs each base zone with its surge variants.
- **Alias map:** writes `src/data/alias-map.json` only on the first run (so manual edits are preserved on subsequent runs). Pre-seeded with known sub-areas from the SOW (Alapere, Ologolo, VGC, etc.).

## 7. Using the bot — staff workflow

### 7.1 Parse an order

1. In any Slack channel the bot has access to, type `/parse-order`.
2. A modal opens with a large text input. Paste the raw WhatsApp or Instagram DM message exactly as received.
3. Click **Parse**.
4. The bot posts a **Review Order** message in the channel.

### 7.2 Reading the Review Order message

Each line item shows one of three states:

| Indicator | Meaning | Action needed |
|---|---|---|
| `✅ Product · Size  ×qty  ₦price` | Matched with high confidence | None — but tap **Edit** if wrong |
| `⚠️ "raw phrase" — select the correct product:` | Ambiguous or price mismatch | Pick from the dropdown |
| `❌ "raw phrase" — no match found` | No product matched | Use **Search all** to find manually |

The **reconciliation banner** at the bottom shows:
- `✅ Matches customer's stated total` — all numbers add up
- `⚠️ Off by ₦X` — a mismatch; the bot will suggest a hypothesis if one exists (e.g. a missing delivery fee)

**Confirm & Push to Zupa** is only active once all items are resolved and the total reconciles.

### 7.3 Resolving an ambiguous item

The dropdown shows up to 5 ranked candidates. The bot's best guess is listed first; items with a `✓` suffix have a price that matches what the customer wrote.

- **Tap a row** → the item flips to ✅ and the running total updates instantly.
- **Search all** → opens a search modal where you can type any product name or size and get up to 25 results. Submit selects the product.

### 7.4 Changing the delivery zone

Tap **Change zone** on the fulfillment row. The modal has two options:

1. **Type the area name** (e.g. `Sangotedo`, `VGC`, `Lekki Phase 1`) — the bot matches it to the closest named zone. If you confirm a correction, it can be saved back to the alias map in Phase 2.
2. **Select a ride-hail tier** — for orders dispatched via Uber or Bolt, pick the correct tier (e.g. `Uber Delivery 9 — ₦9,000`). These are the only rows where Uber/Bolt options appear.

### 7.5 Confirm or reject

- **Confirm & Push to Zupa** — validates all items, emits the Zupa payload (see §8 for wiring), and replaces the message with a success summary.
- **Reject** — prompts a confirm dialog, then archives the message. The order is discarded.

### 7.6 Example order and expected result

Input pasted into the modal:

```
eye -

09028920538

Lekki pickup

Double choc mini 3000
Nutella mini 2900
Banana mini 1800
Orange x choc mini...2100
Chicken pie...2500

Total....12,300(Oluseye)

@oluseye_a
```

Expected review message:
- ✅ All 5 items auto-matched (price tiebreaker resolves "Banana mini" to Banana Bread Mini ₦1,800)
- Fulfillment: Pickup — Lekki (₦0)
- Total ₦12,300 — matches stated total
- Status: Auto-accepted — staff only needs to tap Confirm

## 8. Wiring up Zupa (Phase 2)

The `src/zupa.js` file currently logs the payload to the console. To push confirmed orders to the real Zupa API:

1. Add `ZUPA_API_URL` and `ZUPA_API_KEY` to your `.env`.
2. Open `src/zupa.js` and uncomment the `fetch` block inside `pushToZupa`:

```js
const response = await fetch(process.env.ZUPA_API_URL, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${process.env.ZUPA_API_KEY}`,
  },
  body: JSON.stringify(payload),
});
if (!response.ok) throw new Error(`Zupa API error: ${response.status}`);
return response.json();
```

3. Update the success handler in `src/slack/handlers.js` (`handleConfirmOrder`) to display the real order ID returned by Zupa.

### Payload structure (what gets sent to Zupa)

```json
{
  "status": "confirmed",
  "source": "whatsapp",
  "raw_message": "…original text…",
  "customer": { "name": "Oluseye", "instagram": "@oluseye_a", "phone": "09028920538" },
  "fulfillment": {
    "type": "pickup",
    "branch": "Lekki",
    "address": null,
    "zone_id": null,
    "zone_name": "Pick up LEKKI",
    "delivery_fee": 0
  },
  "items": [
    {
      "size_id": "260fce18-766e-4e80-814b-f673b5f9283b",
      "product_name": "Double Choc",
      "size": "Mini",
      "qty": 1,
      "unit_price": 3000,
      "line_total": 3000,
      "match": "auto"
    }
  ],
  "items_subtotal": 12300,
  "order_total": 12300,
  "reconciliation": "matched",
  "confirmed_by": "U0SLACKUSERID",
  "notes": [],
  "overrides": []
}
```

`size_id` and (where applicable) `zone_id` are the authoritative UUIDs that Zupa consumes. All name fields are display-only.

## 9. Extending the alias map

`src/data/alias-map.json` maps customer-spoken sub-area names to canonical zone IDs. This is the key file for improving delivery zone resolution over time.

**Format:**

```json
{
  "ALAPERE": {
    "zoneId": "b161e54b-ac1d-450d-993b-6138b8678a62",
    "zoneName": "Ketu (Mainland Store)",
    "branch": "Mainland"
  }
}
```

**Rules:**
- Keys must be **uppercase** with no extra whitespace.
- `zoneId` must be a valid ID from `cities.json`. Cross-check in `src/data/cities.clean.json`.
- `branch` must be `"Lekki"`, `"Mainland"`, or `"Opebi"`.

**To add a new entry** — for example, "Gbagada Express" should map to Gbagada (Mainland Store):

```json
"GBAGADA EXPRESS": {
  "zoneId": "79c94848-354f-46ac-a4b6-006276d5b9c7",
  "zoneName": "Gbagada (Mainland Store)",
  "branch": "Mainland"
}
```

The bot picks up alias map changes **without restarting** — it reads the file at require-time, so a restart is needed after edits. In Phase 2, when a staff member corrects a zone for an unmatched address, the correction can be written back to this file automatically.

## 10. Troubleshooting

### `/parse-order` command doesn't appear

- Confirm the slash command was added in **Slash Commands** (step 2.5) and the app was reinstalled to the workspace after adding it.
- Check that the bot was invited to the channel: `/invite @ZupaOrderParser`.

### Bot goes offline / Socket Mode disconnects

- Verify `SLACK_APP_TOKEN` starts with `xapp-` (not `xoxb-`). These are different tokens.
- Check that the App-Level Token has the `connections:write` scope (step 2.2).
- Socket Mode is not affected by firewalls on the inbound side — the bot initiates the connection outward.

### "Order state not found" after confirming

- The in-memory state resets when the bot restarts. If the bot was restarted between parsing and confirming an order, re-paste the raw message with `/parse-order`.
- Phase 2 should persist order state to a database (Redis or PostgreSQL) to survive restarts.

### Product matching is wrong

- Check if the product name in `products.json` contains unusual characters (slashes, parentheses). The matcher normalises these but the clean data might need regenerating: `npm run clean-data`.
- For stubborn mismatches, use **Search all** in the UI — it runs a fresh search on any phrase you type.
- For a systematic fix, adjust the scoring threshold (`HIGH_CONFIDENCE_SCORE` in `src/parser/index.js`, currently `0.7`) or the ambiguity window (`0.85` multiplier).

### Delivery zone not resolving

- If a sub-area isn't in the alias map, add it (see §9).
- If the total gap doesn't match any zone's base fee, the reconciliation will show "mismatch" — staff use **Change zone** to pick the correct one manually.
- Surge zones are never auto-selected from an address. The bot selects the base zone; if the customer's total implies surge (because the gap matches the surge fee rather than the base fee), the reconciler auto-upgrades to the surge variant.

### "Zupa push failed"

- This means the `pushToZupa` function threw. In Phase 1 (console-only mode) this should never happen unless there is a code error. Check the terminal output for the stack trace.
- In Phase 2 (real API), verify `ZUPA_API_URL` and `ZUPA_API_KEY` are set and the Zupa API is reachable.
